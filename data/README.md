# data/ — OxFunc projections

This is the Handbook's only mechanically synchronized organ (see `OPERATIONS.md` section 2).
Everything here is generated by `tools/efh-ingest` and is regenerable; never hand-edit.

Regenerate: `cargo run` in `tools/efh-ingest` (reads the sibling OxFunc repo read-only;
override the location with `EFH_OXFUNC_ROOT`). Output is deterministic — byte-identical for a
fixed OxFunc state — and carries no timestamps. Provenance (OxFunc commit, export snapshot
identity, registry fingerprint) lives in `index.json`; the F18 localization organ additionally
records its exact source path, full commit, and byte SHA-256. Per-function files omit that global
metadata so they change only when their content changes.

## Shape

- `functions/<function_id>.json` — one file per function entry (541 entries).
- `index.json` — provenance, counts, and the row list.
- `localization/microsoft-support-function-index.json` — the complete 20,360-row, 40-locale
  Microsoft Support alphabetical-index harvest from OxFunc W28. The eight source columns are
  preserved as harvested; only relative Microsoft Support links are made absolute.

## The spine, and the 534 → 541 reconciliation

The row spine is OxFunc's published snapshot export (534 rows: 511 functions + 23 operators).
Seven of those rows are combined byte-variant documentation rows (`FIND, FINDB`; `LEFT, LEFTB`;
`LEN, LENB`; `MID, MIDB`; `REPLACE, REPLACEB`; `RIGHT, RIGHTB`; `SEARCH, SEARCHB`) — an
artifact of Microsoft documenting each pair in one article. The OxFunc runtime registry (the
canonical metadata source) models the variants as distinct functions with distinct semantics,
and so does the Handbook: each combined row is split into per-function entries, giving
541 entries covering the 534 published rows. Every entry's `published_row_id` records which
published row it came from.

## Field notes

- `registry_backed: false` marks the 16 entries that exist on the published surface but not in
  the runtime registry: 13 deferred functions and three formula-layer forms (`LET`, `LAMBDA`,
  the implicit-intersection operator) whose binding semantics are owned upstream of the
  function library.
- `signature: null` + `signature_placeholder: true` marks rows whose upstream signature is
  still a placeholder (229 today). Render as "no signature data", never as a real signature.
- `admission.label` is `supported` or `deferred` (with the deferral reason); the deferred set
  is the 17-row inventory from the upstream deferral register.
- `localized_names` contains only function-resolved names from the 40-locale harvest. Article GUID
  is not treated as function identity: the ten IS functions share one article, seven byte-function
  pairs have combined source rows, and FORECAST.LINEAR and IMAGINARY have no distinct W28 row.
  Those pages leave
  `localized_names` empty and explain the source relationship in `localization`; every raw name,
  localized one-line help string, category, version marker, and link remains in the localization
  organ.
- `localization` is an object for all 518 functions and `null` for all 23 operators. Its honest
  association states are `function/article_unique` (491 pages),
  `shared_article/english_name_match` (FORECAST, whose sole en-US W28 row names FORECAST even
  though its article GUID is also used by FORECAST.LINEAR),
  `shared_published_row/combined_row` (14 pages),
  `shared_article/unresolved_shared_guid` (10 pages), and
  `function/missing_source_row` (FORECAST.LINEAR and IMAGINARY).
- The localized descriptions are Microsoft Support alphabetical-index summaries. They are not
  represented as complete localized help articles: the source does not contain argument tables,
  remarks, or examples.
- When the live registry has no short description, the official English documentation description
  supplies `descriptions.short`. COPILOT and JIS take their complete English docs object (URL plus
  description) from the W28 en-US row because the baseline catalog descriptions are blank; their
  `vintage.docs` and `vintage.descriptions` both name that W28 basis.
