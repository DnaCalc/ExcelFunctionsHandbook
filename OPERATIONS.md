# Operations

Status: `active`
Scope: execution doctrine for The Handbook of Excel Functions. Subordinate to `CHARTER.md`.

## 1. Cross-repo Rules

1. This repo may **read** sibling repos under `C:\Work\DnaCalc` (OxFunc, DnaOneCalc, OxReplay, …)
   for contracts, registries, evidence, and alignment.
2. This repo must **not write** to sibling repos. Anything the Handbook learns that a sibling
   should absorb is routed as a handoff note in `docs/handoffs/` and delivered through that
   repo's own process.

## 2. Organs and Mutability

| Path | Owner | Mutability |
|---|---|---|
| `data/` | efh-calcfunc (mechanical) | Regenerated by sync only; never hand-edited |
| `content/` | Handbook curation | Hand/agent-curated; never touched by sync |
| `implementations/` | Handbook curation | Curated; admitted only via suite verification |
| `vectors/` | Handbook curation | Versioned suites; append-mostly (section 5) |

| `site/` | efh site generator | Regenerated from data, reference records and prose |
| `tools/`, `tests/` | Engineering | Ordinary code review |

## 3. Sync Doctrine (Handbook ↔ DnaCalc)

1. `data/calcfunc/pin.json` names one DnaCalc commit. `tools/efh-calcfunc/regenerate.py` reads that
   commit only: the calc-func catalogue, the calc-fml built-ins, `witness-status.tsv`,
   `witness-differences.tsv` and `docs/generated/`. It writes `data/calcfunc/` and the signature,
   arity and admission fields of `data/functions/`. See `tools/efh-calcfunc/README.md`.
2. To move the pin, check out the new commit, run `cargo xtask corpus --oracle --no-capture` there,
   and pass its output with `--corpus-run`. Review the diff before committing.
3. Identity, category and localization fields in `data/functions/` come from the frozen spine in
   `data/`. The earlier ingest tool was retired with its source repository.
4. Nothing outside `data/` is modified mechanically, except the descriptions and starter reference
   records of entries added to the catalogue.
5. Divergences the Handbook discovers that belong upstream are filed to `docs/handoffs/`.

## 4. Determinism Requirements

1. `data/calcfunc/` is byte-stable for a fixed pin and a fixed corpus run, with one exception: the
   environment variants evaluate calls on the machine running the script, and the x87 kernels run
   the CPU's own instructions on x86_64. Each such record names the CPU in `evaluated_on`.
2. Function JSON and site output are stable for identical source inputs.
3. The build inventory records the source revision and tree state.
4. ULP Atlas plates regenerate byte-stably from the suite version that produced them.

## 5. Suite Versioning

1. A suite is `vectors/<function_id>/vN/` containing `suite.jsonl` (bits-hex payloads) and
   `MANIFEST.json` (count, sha256, oracle provenance: Excel build, platform, capture route).
2. Suites are append-mostly; any change to existing vectors bumps `N`.
3. Verification and exactness claims always name the suite version and manifest hash they
   were verified against. Which words may state such a claim is governed by `CHARTER.md`
   section 7 rule 8; until a suite publishes here, none of them may.
4. Published suites are downloadable from the site and are part of the public API.

## 6. Ratchets (CI)

Monotonic counters, enforced by tests: curated pages, documented behaviours, suite-tested
implementations, suite-covered functions. Placeholder/uncurated counts are monotonically
non-increasing. A regression fails CI.

## 7. Evidence Intake

1. The contribution form collects function, contribution kind, Excel build, reproduction details
   and optional contact information into the Handbook's private store.
2. Submissions are reviewed before their content enters a function record or source document.
3. Accepted contributions are credited with the contributor's permission.
4. Nothing is automatically admitted as fact.

## 8. Tooling Map

| Tool | Language | Role |
|---|---|---|
| `tools/efh-calcfunc` | Python, Rust (reads a pinned DnaCalc checkout) | Signatures, arity, admission, implementation state, variants and quoted code in `data/` |
| `tools/efh-site` | Rust (standalone) | Reference HTML and JSON; local link/claim checks; no publication step |
| `tools/efh-engine` | Rust + build script | OneCalc browser wasm and the shared evaluation bridge |
| `tests/` | per language | Vector runners, ratchets, determinism drills |

## 9. Current work

All 554 entries use the same reference structure and stable JSON URLs. Further work prioritizes
thin explanations, measured version comparisons, implementation guidance and published suites.
Browser calculation uses OneCalc; the local server runs the same wasm module for `/api/eval`.
Local checks and the private contribution store are described in the tooling documentation.
Build and test locally; hosting and deployment are separate operations.
