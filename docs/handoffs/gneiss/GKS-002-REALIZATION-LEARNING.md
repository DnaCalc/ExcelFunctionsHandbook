# GKS-002 — Realization Learning as an Explicit Gneiss Process

Date: 2026-07-18  
Source realization: The Handbook of Excel Functions  
Target: Gneiss project governance and realization register

## Pressure Observed

Gneiss intends to learn from demanding domain realizations, but there is no compact, durable
contract for moving a local workaround or design discovery into the meta-system. Without one,
either Gneiss speculates too early or realizations accumulate unstructured conventions that never
teach the substrate.

## Proposed Loop

```text
domain pressure -> local experiment -> real artifact + drill -> realization finding
-> Gneiss decision -> versioned generic contract -> realization upgrade
```

The source realization must remain free to experiment without waiting for generic adoption. Gneiss
must remain free to adopt, generalize, retain as guidance, defer, or reject the finding.

## Candidate Finding Shape

Each handoff records:

- realization and responsible steward;
- Gneiss versions/profile under test;
- observed domain pressure and concrete forcing example;
- local solution and artifacts;
- proposed generic principle;
- what must remain domain-specific;
- counterexamples, risks, and falsification signal;
- minimal cross-domain or protocol-neutral drill;
- proposed destination: calculus, Cell/API, Public Surface, profile/toolkit, or guidance;
- disposition and eventual adoption version.

## Candidate Generic Gneiss Contract

1. Realization findings are attributable testimony, not automatic amendments.
2. Adoption is an explicit Gneiss decision with a destination and version.
3. Domain code never becomes a dependency of the Gneiss kernel; reusable fixtures are extracted
   into protocol-neutral form.
4. A realization pins the Gneiss versions it evaluated so later changes cannot rewrite what was
   learned.
5. Local extensions stay visible until adopted or retired.
6. Rejected and superseded findings remain in history with reasons.

## Proposed Destination

- Add a root `REALIZATIONS.md` defining the process and a small current-realizations register.
- Link it from the Gneiss README.
- Add realization intake and extracted drills to the roadmap's external-probe work.
- Keep the process lightweight; do not introduce a new kernel primitive.
