# GKS-003 — Candidate Experimental Gneiss Knowledge System Profile

Date: 2026-07-18  
Source realization: The Handbook of Excel Functions  
Target: Gneiss Public Surface profile/manifest work

## Pressure Observed

The phrase “A Gneiss Knowledge System” needs a machine-readable scope before realizations publish
incompatible badges. The Handbook needs to state that Gneiss governs its load-bearing claims while
Git, code, vectors, projections, and documents remain evidence organs. It also needs to declare
local presentation lenses without pretending they are belief contexts.

The Handbook's human design profile is `GNEISS-PROFILE.md`.

## Candidate Profile Fields

- schema/profile version;
- system identity and steward;
- category-claim status (`designed`, `experimental`, or earned conformance);
- covered boundaries and claim families;
- integration mode(s): foundation, embedded, sidecar, presentation-only;
- Gneiss protocol, implementation, evaluator, and Public Surface versions;
- default public view;
- evidence organs and survival/retention promises;
- presentation lenses and invariants;
- drills with status and evidence references;
- known limitations;
- local extensions and divergences.

## Candidate Generic Rules

1. Before ratified conformance drills exist, the strongest badge is **Experimental Gneiss
   Knowledge System**.
2. A profile distinguishes the category claim from an implementation choice and earned
   conformance.
3. The profile states exactly what Gneiss governs; it never implies every byte is ledgered.
4. Presentation-lens declarations are separate from evaluation-context declarations.
5. A failed or stale drill weakens the visible claim rather than leaving a decorative badge.
6. Publication pins evaluator/profile versions and the evidence required for replay.

## Proposed Destination

- Add a candidate versioned profile schema under `Gneiss/profiles/`.
- Add generic profile and presentation-lens drills beside it.
- Keep the schema explicitly experimental; it is not yet a conformance standard.
- Use the Handbook profile as a realization fixture without copying `efh.*` vocabulary into
  Gneiss.
