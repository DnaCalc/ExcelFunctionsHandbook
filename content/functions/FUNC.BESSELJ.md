# BESSELJ

## What it does

`BESSELJ(x,n)` evaluates the order-n Bessel function of the first kind. It is a special function used in radial and oscillatory problems, rather than an elementary trigonometric function. The order is truncated to an integer.

## Try it

The recorded `=BESSELJ(0,0)` returns `1.00000000283141` (`0x3ff0000000c292b1`). The mathematical value is exactly one; this example exposes the approximation in the seed rather than an input-rounding issue. FN-BESSELJ-001 retains the captured answer and its environment.

`=BESSELJ(0,3)` returns zero under the current route. For a nonzero example, the order-two value at x=3 comes from the recurrence `J2(3)=(2/3)*J1(3)-J0(3)`, so both order-zero and order-one seeds contribute.

## Quirks

Nonnumeric arguments give `#VALUE!`. A negative order is rejected before truncation, so `n=-0.5` gives `#NUM!`; a nonnegative fractional order truncates toward zero. The current limit after truncation is 10,000,000.

Negative x uses integer-order parity: an odd order changes sign and an even order does not. The order-zero approximation at zero is slightly high in the recorded capture. Do not insert a mathematical `J0(0)=1` shortcut into a compatibility implementation.

The current large-argument admission compares the stored phase with `2^27-1`. Its order-zero phase constant is `0.785398164`, order-one `2.356194491`; a forward recurrence needs both seed admissions. These are measured scope limits, separately from the remaining numerical-body discrepancies.

## How to implement

Validate the numeric input and order before selecting a route. The current implementation uses licensed fixed rational seeds for J0 and J1, a forward recurrence when `abs(x)>n`, and a published adaptive backward program otherwise. For negative x, evaluate at its magnitude and apply the order's parity.

For forward order n, set `tox=2/abs(x)`, `previous=J0(abs(x))`, `current=J1(abs(x))`. For j from one through `n-1`, compute `next=(j*tox)*current-previous`, then advance the two states. The current J/Y outer recurrence uses ordinary binary64 operations with subnormal operands/results flushed to zero. K's stored-PC64 recurrence is a separate choice; do not transfer it automatically.

Worked seed at zero: the small-J0 numerator's constant is `57568490574` and its denominator's is `57568490411`. Their binary64 quotient is `1.00000000283141`, the recorded result. For mathematical J0 the defining series instead has constant one and every higher term vanishes at zero.

The fixed seed/backward helpers credit SheetJS/bessel under Apache-2.0, with project changes and measured phase controls. The generic J/Y body remains a published-method candidate with residual differences. Its coefficient choices, phase grouping and boundaries do not amount to an identification of Microsoft's private code or a whole-domain equality claim.

### FN-BESSELJ-001: BESSELJ at zero and order zero is slightly above one

*Excel differs from the mathematical answer; measured; recorded 2026-11-06.*

In the retained catalogue capture, BESSELJ(0,0) returns 1.00000000283141 (0x3ff0000000c292b1),
while the mathematical Bessel function J0(0) is exactly 1. The raw answer, saved workbook cache
and answer after reopening retain that same value. This is one captured input on the named
Excel environment, not a general accuracy statement.

| Call | Inputs (binary64) | Excel | Correct value | Recorded in |
|---|---|---|---|---|
| `=BESSELJ(0,0)` | as typed | `1.00000000283141` (`0x3ff0000000c292b1`) | `1` (`0x3ff0000000000000`) | Excel 16.0.20527.20088 Current Channel, Windows 64-bit (NT 10.0.26200), AMD Ryzen 7 4800H, en-ZA, workbook Compatibility Version 1 |

Correct value: Exact identity J0(0)=1: in the defining series in NIST DLMF 10.2.2
