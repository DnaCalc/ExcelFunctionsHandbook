# VARP

## What it does

`VARP(number1, [number2], ...)` measures population variance. It measures squared distance from the mean, so its units are the square of the input units. The divisor is `n`: use this when the observations constitute the whole population. It is a compatibility name; the dotted name makes the sample/population choice clearer in new workbooks.

## Try it

`=VARP(-2,0,2)` returns approximately `2.66666666666667`. The mean is zero and the squared deviations total eight. Divide by three.

## Quirks

Numbers in references and arrays count, including zero; referenced text, logical values and empty cells do not. Direct logical values and numeric text can count, so moving a constant into a cell can change the admitted data set. An empty numeric set gives `#DIV/0!`; a one-value population has zero spread. A centered mathematical formula alone does not reproduce the observed numerical path.

## How to implement

Apply the collection rules above, then use the [stored variance recipe](FUNC.VAR.S.md#how-to-implement). This function uses the **population** branch, with final divisor `n` and no square root.

For the three values `-2,0,2`, the stored totals are `S=0`, `Q=8`, `T=0`. The population numerator is `3*8-0=24` and the stored divisor is `3*3=9`. Do not replace the population operation tree by the sample tree with a changed final divisor.

The same two guards can redirect this call to the centered pass. For `1000,1001,1002`, that pass sums `1+0+1=2` and divides by `3`. The exact scalar guard edges are measured; their transfer to references and arrays remains open. Nonfinite raw-moment fallback is inferred. No Handbook vector suite is published for this function.

## Alternatives

Use [VAR.P](FUNC.VAR.P.md) as the explicit modern spelling of population variance. [VAR.S](FUNC.VAR.S.md) uses the sample divisor, and [STDEV.P](FUNC.STDEV.P.md) returns a standard deviation in the original units.

### FN-VAR.S-001: The variance family uses raw moments with stored steps, and two tests switch it to a centered sum

*Excel differs from the mathematical answer; measured; recorded 2026-11-04.* Applies to STDEV, STDEV.P, STDEV.S, STDEVA, STDEVP, STDEVPA, VAR, VAR.P, VAR.S, VARA, VARP, VARPA.

With RN(v) meaning v rounded to 64 bits on the x87 unit and then stored to binary64, S the
running RN sum of the n values and Q the running RN sum of RN(x*x), the sample variance is
RN(RN(Q - RN(RN(S*S)/n))/(n-1)) and the population variance RN(RN(RN(n*Q) - RN(S*S))/RN(n*n)).
Excel then uses a centered sum instead, adding RN(d*d) with d = RN(x - mean) and dividing by
n-1 or n, when either of two stored tests holds: RN(RN(RN(S*S)/n)/Q) > 0.99, or
RN(variance*1000) <= |RN(S/n)|. The STDEV functions are the root of this, rounded to 64 bits
and then stored. So the answer depends on which path a call takes: the first two VAR.S calls
below differ by a few input steps in two arguments, the first passes the 0.99 test and is
correctly rounded, and the second takes the raw moments and lands 76 units high. The next pair
shows the size test: scaling the inputs by 4 leaves the first path.
