# VAR.S

## What it does

`VAR.S(number1, [number2], ...)` measures sample variance. It measures squared distance from the mean, so its units are the square of the input units. The divisor is `n-1`: use this when the observations are a sample of a larger population.

## Try it

`=VAR.S(-2,0,2)` returns `4`. The mean is zero and the squared deviations total eight. Divide by two.

## Quirks

Numbers in references and arrays count, including zero; referenced text, logical values and empty cells do not. Direct logical values and numeric text can count, so moving a constant into a cell can change the admitted data set. An empty numeric set gives `#DIV/0!` and a one-value sample does too. A centered mathematical formula alone does not reproduce the observed numerical path.

## How to implement

Use the recorded staged algorithm when Excel compatibility is the goal. Here `R(op)` means: evaluate **one** operation with a 64-bit significand and extended exponent range, round to nearest with ties to even, then store to binary64 (53 significant bits). It is two rounding steps, not the language's ordinary double operation. An arbitrary-precision binary implementation can perform these steps explicitly; the product uses an x87 model. Disable contraction into a fused multiply-add.

1. Collect the admitted values in their traversal order. Set `n` to the count, `S=0`, `Q=0`. Reject an empty collection, and reject `n<2` for a sample.
2. For each `x`, assign `S=R(S+x)` and `Q=R(Q+R(x*x))`. Then set `T=R(S*S)` and `m=R(S/n)`.
3. For a sample, compute `v=R(R(Q-R(T/n))/(n-1))`. For a population, compute `v=R(R(R(n*Q)-T)/R(n*n))`. These expressions have different stored steps: do not algebraically combine them.
4. Test `R(R(T/n)/Q)>0.99` and `R(v*1000)<=abs(m)`. If either holds, recompute `C` from zero by `d=R(x-m)`, `C=R(C+R(d*d))`, and return `R(C/(n-1))` for a sample or `R(C/n)` for a population. The current code also takes this centered pass when raw moments are nonfinite.
5. For a standard deviation, take the square root at 64-bit significand precision and then store to binary64.

Worked raw path: for `-2,0,2`, `n=3`, `S=0`, `Q=8`, `T=0`, `m=0`. Neither guard holds. Sample variance is `8/2=4`; population variance follows `(3*8-0)/9=8/3`. Sample standard deviation is `2`.

Worked centered path: for `1000,1001,1002`, `S=3003`, `Q=3006005`, `T=9018009`. The cancellation ratio is about `0.9999993`, above `0.99`. With `m=1001`, the centered squares are `1,0,1`; their sum is `2`, giving sample variance `1` or population variance `2/3`.

The scalar guard edges and stored operations have discriminating recorded answers; range/array transfer at the newly located edges remains open. The overflow fallback is an inference from finite recorded answers, and the magnitude comparison has not been separated from its division-based rearrangement. This recipe describes a reconstruction over the cited evidence, not Microsoft's private source code.

## Alternatives

Use [VAR.P](FUNC.VAR.P.md) for the other variance divisor. [STDEV.S](FUNC.STDEV.S.md) expresses spread in the original units. Use VARA or VARPA only when logical values and referenced text belong in the data set.

### FN-VAR.S-001: The variance family uses raw moments with stored steps, and two tests switch it to a centered sum

*Excel differs from the mathematical answer; measured; recorded 2026-11-04.* Applies to STDEV, STDEV.P, STDEV.S, STDEVA, STDEVP, STDEVPA, VAR, VAR.P, VAR.S, VARA, VARP, VARPA.

With RN(v) meaning v rounded to 64 bits on the x87 unit and then stored to binary64, S the
running RN sum of the n values and Q the running RN sum of RN(x*x), the sample variance is
RN(RN(Q - RN(RN(S*S)/n))/(n-1)) and the population variance RN(RN(RN(n*Q) - RN(S*S))/RN(n*n)).
Excel then uses a centered sum instead, adding RN(d*d) with d = RN(x - mean) and dividing by
n-1 or n, when either of two stored tests holds: RN(RN(RN(S*S)/n)/Q) > 0.99, or
RN(variance*1000) <= |RN(S/n)|. The STDEV functions are the root of this, rounded to 64 bits
and then stored. So the answer depends on which path a call takes: the first two VAR.S calls
below differ by a few input steps in two arguments, the first passes the 0.99 test and is
correctly rounded, and the second takes the raw moments and lands 76 units high. The next pair
shows the size test: scaling the inputs by 4 leaves the first path.
