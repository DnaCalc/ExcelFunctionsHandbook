# GAMMAINV

## What it does

`GAMMAINV(probability, alpha, beta)` inverts the gamma cumulative distribution. Alpha is a positive shape and beta a positive **scale**. This is the compatibility name.

## Try it

`=GAMMAINV(0.5,1,2)` is about `1.38629436111989`: the median of the shape-one distribution with scale two is `-2*ln(0.5)`.

## Quirks

Alpha and beta must be positive; nonpositive shape or scale gives `#NUM!`, while text arguments are documented as `#VALUE!`. The opened legacy page rejects probabilities outside `[0,1]`. The current shared helper returns zero at `p=0` and rejects `p=1` with `#NUM!`, since no finite upper support endpoint is available.

Microsoft describes this legacy inverse as an iterative search over GAMMADIST with a 100-iteration limit and `#N/A` on failure. Its current GAMMA.INV page describes 64 iterations and also `#N/A`. This is a difference in published descriptions of the two spellings; it does not establish a measured change between Excel builds or identify either internal search.

## How to implement

The current helper searches the positive binary64 lattice rather than stopping at a decimal tolerance:

1. Validate shape, scale and probability. Return zero at `p=0`; reject `p>=1` or `p<0`.
2. Start the upper bound at `hi=beta*max(alpha+10*sqrt(alpha)+10,1)`. The code allows up to 200 doublings while the generic forward value `P(alpha,hi/beta)` is below `p`.
3. With lower bound zero, encode the nonnegative bounds as unsigned binary64 bit integers. Their ordering agrees with numeric ordering.
4. While the two encodings differ by more than one, bisect their integer encodings and decode the middle value `x`. If `P(alpha,x/beta)>=p`, move the upper encoding to it; otherwise move the lower encoding.
5. Return the upper value once the encodings are adjacent. This chooses the first representable candidate meeting the current forward test under the maintained bracket.

For shape one, scale two and probability one half, the mathematical equation is `1-exp(-x/2)=0.5`; its solution is `-2*ln(0.5)`, about `1.38629436111989`. That explains the scale and the example, not every last bit of the generic forward search.

The inverse callback calls `regularized_gamma_p` directly. It does not use every special-case wrapper of public GAMMADIST. Its forward approximation, bracket failures and return policy remain separate compatibility obligations; the current problem report still lists distribution mismatches. This is the current implementable candidate, not a recovered Excel search program.

### FN-GAMMA.DIST-005: For a < 1 and x < 1.1, Excel uses TOMS 654 double-precision st200 branch bounds with shared Kahan expm1, forcing even LSBs when P < 0.5

*Detail for matching Excel's bits; inferred; recorded 2026-11-22.* Applies to CHISQ.DIST, GAMMA.DIST, GAMMA.INV, GAMMADIST, GAMMAINV.

In Excel 16.0.20527, when 0 < a < 1.0 and 0 < x < 1.1 (unit scale x / beta), gratio computes z
= S(a * ln(x)) with x87 PC64 operations and selects the upper-complement branch st200 using
TOMS 654's double-precision (iop = 1) bounds: z >= -ln(2) (-0x1.62e42fefa39efp-1,
0xbfe62e42fefa39ef) when x <= 0.5, and S(a - x) < 0.25 when x > 0.5. Single-bit straddles at x
= 0x3fd965fea53d6e3c vs 0x3fd965fea53d6e3d (a = 0.75) and x = 0.5 vs next_up(0.5) (a = 0.8125)
establish both seams with zero bits of slack. Inside st200, Excel computes expm1(z) via its
shared Kahan excel_expm1_internal(z) routine (not Morris's gratio_rexp rational) and forms P =
0.5 + (0.5 - qans), which by Sterbenz's lemma gives an even LSB (bit 0 = 0) on every output
with P < 0.5 (85 of 85 across consecutive-x sweeps). Separately, for CHISQ.DIST(2*y, 2*a, TRUE)
at a > 20 and y < 1.1, Excel exits the anomalous a > 20 lower-series branch at y == 1.1
(0x3ff199999999999a) while poisson_mass keeps compensated exp until y > 1.1.

### FN-GAMMA.INV-001: Gamma and chi-square inverses use erfinv(p)^2 at a=0.5, Goldstein 451 for a > 1, a 0.9999 complement switch, and damped Halley

*Detail for matching Excel's bits; inferred; recorded 2026-11-22.* Applies to CHIINV, CHISQ.INV, CHISQ.INV.RT, GAMMA.INV, GAMMAINV.

In Excel 16.0.20527, the five gamma and chi-square inverse functions share one unit solver plus
closed forms. At alpha == 0.5 (df == 1), Excel computes erfinv(p)^2 directly using the exact
same four-piece rational/AS 241 tables as NORM.S.INV (omitting sqrt(2) on the central pieces
and scaling the AS 241 tail by 1/sqrt(2)), flushing subnormal y*y to 0.0 inside the unit helper
before multiplying by beta or 2.0. For general shapes, a > 1.0 starts from Goldstein (1973,
CACM Algorithm 451) 7-term stored polynomial a * ((c * c) * c) (with z = -NORM.S.INV(q) on
right-tail CHIINV/CHISQ.INV.RT for df >= 3 so tiny q never collapses 1 - q to 1.0); a < 1.0
uses AS 91 -1.24 * ln(p) power-law or Wilson-Hilferty with a * exp(3 * ln(c)). Above strict
prob > 0.9999 (0x3fefff2e48e8a71e), the Halley residual switches to the upper/lower complement
(comp(prob) - flush(Q) or flush(P) - comp(prob)). The unfactored Halley step uses AS 109
thirding damping on sign changes, a 106-trial budget, and stops on |next - x| <= eps * x
(returning best_x by strict < on |df| without evaluating next) or |last_adj| >= step_limit &&
!improved. Remaining >= 5 ULP misses on GAMMA.INV/GAMMAINV sit almost exclusively in a < 1, y <
1.1 where conditioning ~ 1/a magnifies forward gratio offsets. See
https://github.com/DnaCalc/DnaCalc/blob/344d70dcea3ea77cbbeee1595f96694630a9610a/docs/articles/last-bit-gamma.md
and
https://github.com/DnaCalc/DnaCalc/blob/18828c4446e1375dd58ab855ea87c09d649b2e67/docs/articles/last-bit-normsinv.md.
