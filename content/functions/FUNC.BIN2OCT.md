# BIN2OCT

## What it does

`BIN2OCT(number, [places])` converts binary to octal. The result is text, with optional leading zeros controlled by `places`.

## Try it

`=BIN2OCT("101101",4)` returns `"0055"`. All of these represent the same integer: decimal 45, binary `101101`, octal `55`, and hexadecimal `2D`.

For a negative value, `=BIN2OCT("1111010011",4)` returns `"7777777723"`. Decode `979-1024=-45`, then encode `2^30-45` in ten octal digits. Copying or padding the binary digits would lose the signed value.

## Quirks

These engineering conversions use signed fixed-width encodings, not arbitrary-length integers. The source accepts at most ten digits; a full ten-digit encoding uses 10-bit two’s complement. `1111111111` represents minus one. Invalid source digits or an oversized input give `#NUM!`. For a positive result a width too small gives `#NUM!`. A negative result uses ten digits; the current code still validates an explicitly supplied width before emitting it, despite documentation describing the width as ignored.

## How to implement

Separate input parsing, signed interpretation and output formatting. Uppercase the source, validate its digit set and length, and accumulate `raw=raw*2+digit` with checked integer arithmetic. Only a full ten-digit source with its top bit set is negative: subtract `2^10` to obtain signed integer `v`. Check `v` against the 30-bit signed target range. If negative, encode `2^30+v` in base 8 using ten digits. Otherwise use repeated division by 8, reverse the remainders and left-pad to the requested width. Truncate the width and validate it in the current supported range one through ten. Return text; a decimal number formatted to look similar is a different value kind.

## Alternatives

[OCT2BIN](FUNC.OCT2BIN.md) converts in the reverse direction. [BASE](FUNC.BASE.md) and [DECIMAL](FUNC.DECIMAL.md) provide general radix conversion with different sign rules. A full-width negative engineering encoding is not a minus-prefixed numeral; choose the pair whose sign convention fits your input.

### FN-BIN2DEC-001: Radix converters read empty text as 0, count leading zeros toward the 10-character limit, and ignore places on negative two's-complement outputs while still validating it

*Quirk; measured; recorded 2026-11-22.* Applies to BIN2DEC, BIN2HEX, BIN2OCT, DEC2BIN, DEC2HEX, DEC2OCT, HEX2BIN, HEX2DEC, HEX2OCT.

Across the A-L Engineering radix converters in Excel 16.0 build 20430 and 20527, string inputs
reject any whitespace (including spaces and tabs) with #NUM!, reject logicals with #VALUE!,
count leading zeros toward the 10-character maximum (e.g. HEX2DEC("00000000001") is #NUM!),
accept lowercase hex digits, and treat the empty string "" as 0 (HEX2BIN("") = "0"). When
outputting a negative number in two's complement, Excel always emits 10 digits regardless of
places (DEC2BIN(-512, 1) = "1000000000"), yet still requires an explicit places argument to
truncate into 1..=10 (#NUM! for 0 or 11).
