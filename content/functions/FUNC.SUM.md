# SUM

## What it does

`SUM(number1, [number2], ...)` adds individual numbers and numbers held in ranges or arrays. A range keeps a total tied to the cells that contain the data; mixing a range with further scalar arguments adds all of them.

## Try it

`=SUM(7,-2,5)` returns `10`. With B2:B4 containing `7`, the text `pending`, and `5`, `=SUM(B2:B4)` returns `12` because the referenced text is skipped.

Direct constants use a different admission rule: `=SUM(1,TRUE,"2")` adds one, one and two to give four. Putting those three values in an array, `=SUM({1,TRUE,"2"})`, admits only the numeric one. A cell's numeric value and its text spelling are different inputs.

## Quirks

Referenced text, logical values and blanks are skipped; numeric zero participates. Direct logicals and numeric text convert, while unconvertible direct text causes `#VALUE!`.

Recorded error controls give direct-argument failures priority over errors held inside ranges or arrays. For example, `SUM({1,#REF!},"a")` gives `#VALUE!`. Among held errors, reading order matters. A later worksheet error can also determine the result after the numeric accumulator has overflowed.

Changing the order of large positive and negative terms can change a floating-point sum. Compensation or sorting is a different numerical recipe, even when it is more accurate mathematically.

## How to implement

1. Preserve each argument's origin: direct scalar, reference or array. Validate direct arguments through numeric conversion first, in argument order, before processing held errors.
2. Visit arguments in order. For a reference visit areas in order and cells in row order; for an array visit elements in row order. Admit held numbers, skip held text/logicals/blanks, and propagate errors under the priority above.
3. Begin with `total=0`. For each admitted number x, assign `total=R(total+x)`, where [R](../model/09-staged-arithmetic.md) rounds to a 64-bit significand and then stores to binary64. Keep one store per addition. Publish the final number under the worksheet finite/subnormal policy.

For `7,-2,5`, the accumulator is `0 → 7 → 5 → 10`. A direct scalar that converts successfully must still be added at its original traversal position; the initial validation pass is not an instruction to sum scalars ahead of ranges. The current implementation also reads arrays boxed inside a GROUPBY result through to their elements. Keep that extension distinct from ordinary rectangular-array collection. The cited source and captures establish these specific routes; no published Handbook suite is supplied here.

### FN-SUM-001: SUM evaluates all direct-argument errors before held reference/array errors, and overflow does not mask later errors

*Quirk; measured; recorded 2026-11-22.*

In Excel 16.0.20527.20088, SUM checks direct scalar arguments (including text-to-number
coercion #VALUE!) in argument order before reporting any error held inside a reference or array
argument, so =SUM(A1:B2,"a") and =SUM({1,#REF!},"a") both return #VALUE! even when B1 holds
#N/A. Among held errors, SUM follows argument order, and a numeric overflow to #NUM! does not
stop reading later arguments, so =SUM(9.99999999999999E+307,9.99999999999999E+307,B1) returns
#N/A.

| Call | Inputs (binary64) | Excel | Recorded in |
|---|---|---|---|
| `=SUM({1,#REF!},"a")` | as typed | `#VALUE!` | Excel 16.0.20527.20088 Current Channel, Windows 64-bit (NT 10.0.26200), x86-64, AMD Ryzen 7 4800H, en-ZA |
| `=SUM(A1:B2,{1,#REF!})` | as typed | `#N/A` | Excel 16.0.20527.20088 Current Channel, Windows 64-bit (NT 10.0.26200), x86-64, AMD Ryzen 7 4800H, en-ZA |
| `=SUM(9.99999999999999E+307,9.99999999999999E+307,B1)` | as typed | `#N/A` | Excel 16.0.20527.20088 Current Channel, Windows 64-bit (NT 10.0.26200), x86-64, AMD Ryzen 7 4800H, en-ZA |

### FN-SUM-002: SUM, AVERAGE, and AVERAGEA apply Excel's 50-exponent cancellation snap once at the final numeric addition

*Detail for matching Excel's bits; inferred; recorded 2026-11-22.* Applies to AVERAGE, AVERAGEA, SUM.

In Excel 16.0.20527 (dc-ss3b), SUM snaps its final result to +0 when the last left partial
sum's binary exponent exceeds the sum's binary exponent by at least 50 (so SUM(0.1,0.2,-0.3)
returns +0 rather than 2^-54). A trailing numeric 0 counts as the final addition and suppresses
the snap (SUM(0.1,0.2,-0.3,0) returns 2^-54, 0x3c90000000000000), whereas trailing cell text,
logicals, and blanks are skipped and do not suppress it. AVERAGE and AVERAGEA apply the same
rule to their numerator before dividing by the count; SUMPRODUCT does not snap.

Basis (inferred): Measured across 98+ Excel 16.0.20527 probes in dc-ss3b
(docs/research/sum-cancellation-2026-11-12.md) covering scales 2^-900 to 2^900, exponent gaps
49 vs 50, zero vs skipped tails, and AVERAGE/AVERAGEA/SUMPRODUCT controls; full-bank SUM
(1,211/1,211), AVERAGE (1,222/1,222), and AVERAGEA (1,212/1,212) remain matched.

Inferred, not measured: That the shared post-addition snap uses the exact 50-exponent threshold
across every binade is inferred from the dc-ss3b power-of-two boundary sweeps; the raw probe
JSON files were archived to R2 (research/round53/20261112-fn2-0327/) rather than committed to
git.
