`COPILOT` puts a language model behind a cell. It is the first entry in this catalog whose
documentation states, in Microsoft's own words, that the model "will evolve and improve in the
future and formula results may change over time, even with the same arguments."

That sentence deserves to be read as a specification, not as a caveat. Every other function in
the Handbook is a mapping from arguments to a result; the Handbook's whole apparatus — vector
suites, oracles, ULP residuals, last-bit agreement — presumes that a fixed input has a fixed
correct answer. `COPILOT` is documented as not having that property. It is the function that
falls outside the Handbook's method, and saying so is more useful than pretending otherwise.

The reference engine (OxFunc) records it as **deferred**, with the reason **"Deferred with the
external/provider family for the current version."** The projection is the sparsest in this
batch: `metadata_status: catalog_only`, no XLL code, no arity, no signature, no classification
axes, and — unusually — **no English description at all** in the catalog snapshot. The function
is newer than the data behind this Handbook.

## What it computes

An answer generated by an AI model from a prompt you write and data you point at.

Two structural facts distinguish it from "an AI chat box in a cell", and both come from the
documentation:

1. **It only sees what you give it.** Microsoft states that the function "only has access to
   data provided through the context arguments. It does not have access to other data from the
   workbook, enterprise data." The context arguments are the entire input surface. A prompt
   referring to "the sales table" means nothing unless the sales table is passed as a context
   argument.
2. **It can return an array.** The result may be "multiple results as a Dynamic Array that
   spills across the grid" — so `COPILOT` is a spilling function, and its spill height is
   determined by the model's output rather than by the arguments. That is a shape that no other
   function in Excel has: the result *dimensions* are non-deterministic. A `#SPILL!` on
   recalculation is therefore not an anomaly but an expected state.

The argument list interleaves prompt fragments and context references —
`COPILOT(prompt_part1, [context1], [prompt_part2], [context2], …)` — which lets a formula build
a prompt with data spliced into it at chosen points, rather than concatenating everything into
one string.

## Arguments

`COPILOT(prompt_part1, [context1], [prompt_part2], [context2], …)`

- **`prompt_part`** (required, repeating) — Microsoft: "Text that describes the task or question
  for the AI model."
- **`context`** (optional, repeating) — Microsoft: "A reference from the grid that provides
  context or data for the AI model. This can be a single cell or a range."

The position most likely to be misunderstood is `context`, in two ways. First, it is documented
as a *reference* — a range from the grid — not an arbitrary value, which places `COPILOT` among
the reference-aware functions described in
[the call pipeline](../model/03-call-pipeline.md) rather than the values-only majority. Second,
context is the *only* channel: nothing else in the workbook is visible, so an author who
assumes the model can see the sheet it lives on is wrong.

The reference engine records no arity for this id. The alternating, repeating shape above comes
from the documented signature only.

Availability is documented as Excel for Microsoft 365 (desktop and Mac) and the Excel Web App,
and it requires a licence: a Microsoft 365 Copilot add-on licence for work or school accounts,
or Microsoft 365 Premium for individuals.

## Result and edge cases

Text, or a spilled array of values — determined by the model.

The edges here are unlike any other function's:

- **The same formula may return different results at different times.** Microsoft says so
  directly. Nothing about the formula changed; the model did.
- **The result shape may change too.** A formula that spilled three rows yesterday may spill
  five today, colliding with whatever is below it.
- **There is a rate limit, and it is quantified.** A maximum of **100 `COPILOT` function
  calculations every 10 minutes**. This is a genuinely unusual documented constraint: a
  worksheet with 200 such formulas cannot fully recalculate. It also means a full-rebuild
  recalculation of a large workbook is not a neutral operation.
- **Workbook sensitivity labels can block it.** The function "cannot calculate in workbooks
  labeled Confidential or Highly Confidential". Whether a formula works therefore depends on a
  document property, which no other Excel function's result depends on.

## Errors

Microsoft documents six conditions and — refreshingly for this batch — names the error values:

| Condition | Value |
|---|---|
| more than 100 calculations within 10 minutes | `#CONNECT!` |
| the prompt cannot be evaluated | `#VALUE!` |
| the prompt, including context, is too large | `#VALUE!` |
| no Copilot licence available | `#BLOCKED!` |
| no response from the server | `#CONNECT!` |
| workbook classified Confidential or Highly Confidential | `#BLOCKED!` |

This makes `COPILOT` the best-documented user of the extended error family in the whole
catalog. `#CONNECT!` covers both transport failure and rate limiting; `#BLOCKED!` covers both
licensing and policy. Both codes are catalogued in
[the value universe](../model/01-value-universe.md), where `#BLOCKED!` is defined as
"evaluation blocked by policy or a disabled feature" and `#CONNECT!` as "a required service
connection failed" — and the documented mapping above fits those definitions exactly, which is
a small piece of independent corroboration for the Handbook's error model.

## Relationships

- **`TRANSLATE` and `DETECTLANGUAGE`** — the other service-backed functions in the catalog, and
  the closest thing `COPILOT` has to siblings. They raise the same reproducibility questions on
  a much narrower task. Notably, their documentation does *not* name error values, while
  `COPILOT`'s does.
- **`IMAGE` and `STOCKHISTORY`** — provider-dependent, but with answers that exist
  independently of the request. A stock price on a given day is a fact; a `COPILOT` response is
  not.
- **`LAMBDA`** — the other function that changed what a cell can contain, by making values
  callable. The two are the modern boundary-pushers of the function surface from opposite
  directions.
- **The Copilot pane and Copilot in Excel generally** — the user-interface features readers
  confuse this with. Those are interactive and produce edits; `COPILOT` is a formula and
  produces a value that recalculates.

## Notes for implementers

- This function cannot be implemented as a kernel, and it also cannot be *tested* as one. The
  Handbook's four-flavour framework (see
  [implementation options](../model/07-implementation-options.md)) has no meaningful reading
  here: there is no mathematically correct answer to be the yardstick, and no portable
  reproducible flavour is achievable even in principle.
- The result-shape non-determinism is the hardest engineering consequence. A dependency graph
  that assumes stable spill dimensions will thrash; a workbook layout that assumes them will
  break.
- Rate limiting interacts with recalculation in a way no other function does. A calculation
  engine that eagerly recalculates will exhaust the quota; caching is not an optimization here
  but a requirement.
- Context being reference-shaped (rather than value-shaped) is a real classification claim and
  should be modelled as such rather than flattened to "takes a range of values".
- Sensitivity-label gating means the function's availability is a property of the document.
  That is a genuinely new coupling between document metadata and formula evaluation.

## What has not been checked

No Handbook vector suite exists for `COPILOT`, and no Excel-comparison evidence is recorded.
Nobody has checked this function against Excel in the Handbook's record. Every statement above
is Microsoft's documented behaviour, cited as such.

The Handbook should be blunt about a stronger claim than usual: **a value-comparison suite for
`COPILOT` is not merely unbuilt, it is not a coherent artifact.** Microsoft documents that the
same arguments may yield different results over time, so there is no oracle to capture and no
expected value to store. Publishing a suite would be publishing a snapshot of one model
version's opinions, which is not what the Handbook's suites mean.

What can honestly be characterized is the **envelope**: the call surface, the error mapping,
and the shape behaviour. Those are host and service properties, not model properties, and they
are stable enough to record:

1. **Error-value confirmation.** Each of the six documented conditions provoked deliberately,
   confirming the `#CONNECT!` / `#VALUE!` / `#BLOCKED!` mapping. Since this is the catalog's
   clearest documented use of the extended error family, verifying it is valuable well beyond
   this one page.
2. **The rate limit.** 101 calculations inside ten minutes, to confirm the documented boundary
   and to see whether the limit is per workbook, per session, or per account.
3. **Argument shape.** An odd number of arguments; a `context` that is a value rather than a
   reference; a `context` that is a whole-column reference; zero `prompt_part` arguments.
4. **Result-shape stability.** The same formula recalculated repeatedly, recording only the
   spilled dimensions — a measurement of variability that says nothing about the content and is
   therefore reproducible in a way the content is not.
5. **`#SPILL!` interaction.** A formula whose result grows into an occupied cell on
   recalculation.
6. **Sensitivity-label gating.** The same workbook saved under each label, to confirm the
   documented `#BLOCKED!`.
7. **Context isolation.** A prompt that asks about data present in the workbook but *not*
   passed as context, to confirm Microsoft's statement that the function cannot see it. This is
   a security-relevant claim and worth independent confirmation.
8. **Volatility.** Whether the function recalculates on file open, on `F9`, or only on
   dependency change — which, combined with the rate limit, determines whether a large workbook
   is usable at all.

Until the catalog snapshot behind this Handbook carries a description, an arity and a signature
for `COPILOT`, this page is a structural account of a function the Handbook has not
characterised, and it says so.
