# DELTA

## What it does

`DELTA(number1, [number2])` returns numeric one when the two numbers are equal and zero otherwise. The second number defaults to zero. It is an equality indicator, not an approximate-comparison function.

## Try it

`=DELTA(6,6)` returns `1`; `=DELTA(6,7)` returns `0`; `=DELTA(0)` returns `1`. Summing such results counts exact matches.

## Quirks

The recorded wrapper rejects logicals in either position, including TRUE held in a cell, with `#VALUE!`. A referenced blank instead reads as zero. Errors reveal the read order: `DELTA(TRUE,#REF!)` returns `#REF!`, while `DELTA(#REF!,TRUE)` returns `#VALUE!`, because the second scalar is read first.

Equality applies to the represented inputs, with no tolerance. Mathematically equal decimal expressions can arrive as different binary64 values. On Excel 16.0 build 20527, writing a subnormal binary64 value (`±5e-324` through `±(2^-1022 - 5e-324)`) or `-0` to a cell via `Range.Value2` stores `+0`, so `DELTA(±5e-324)` on a cell-written input evaluates `DELTA(0, 0) = 1` ([sweep-questions-1-ANSWERS.md](../notes/evidence/2026-11-08/sweep-questions-1-ANSWERS.md), `C:\Work\DnaCalc\codex-runs\sweep-questions-1\Q1-subnormal-inputs.json`). When a true computed subnormal reaches `DELTA` in a formula (`x` from `EXP(-745)`, `EXP(-730)`, or `EXP(-709)`), `DELTA(x, 0)` and `DELTA(0 - x, 0)` return `0` while `DELTA(x, x)` returns `1` ([FN-ABS-002](../notes/FN-ABS-002.json)). A tolerance comparison is a different operation.

## How to implement

Read and convert the supplied second scalar first, or use zero when it is omitted. Reject a logical and return an error encountered in that position before reading the first scalar. Then read the first scalar under the same nonlogical numeric rules. A referenced blank is numeric zero.

Compare the admitted numbers for equality and return numeric one or zero, rather than logical TRUE or FALSE. For `(6,6)` the indicator is one. Do not flush true subnormals inside the equality check: in DNA Calc (`crates/calc-func/src/catalogue/math.rs`, commit `e042619e35426ffac3d8cfaaa2dd2961abe3d02c`, and `crates/calc-func/src/witness_exec.rs`, commit `c0b94f88ab4e3df5b518329d08ea03cf481abdbe`), `DELTA` compares `a == b` directly while cell-input replay flushes subnormal `Range.Value2` cell writes to `+0`, matching all 1,092 of 1,092 recorded `DELTA` bank rows (`C:\Work\DnaCalc\codex-runs\sweep-report-2.md`). If both inputs are errors, the recorded result is the second error. This read order is part of the implementation; validating left to right changes the answer before the equality test is reached.

## Alternatives

`--(a=b)` expresses a worksheet equality indicator; [GESTEP](FUNC.GESTEP.md) tests an inclusive threshold; [COUNTIF](FUNC.COUNTIF.md) counts matches over a range.

### FN-ABS-002: Subnormal cell writes and *, /, ^ underflows flush to +0, while +, - and EXP(-745) keep subnormals

*Quirk; measured; recorded 2026-11-08.* Applies to ABS, CEILING, CEILING.MATH, CEILING.PRECISE, DELTA, EVEN, EXP, FLOOR, FLOOR.MATH, FLOOR.PRECISE, GESTEP, INT, ISEVEN, ISO.CEILING, ISODD, ODD, QUOTIENT, SIGN, SQRT.

Writing any positive or negative subnormal binary64 value or -0 to a cell via Range.Value2
stores +0 (0x0000000000000000), while normal extremes 2^-1022 (0x0010000000000000) and ±DBL_MAX
(0x7fefffffffffffff) read back intact. In the 430 recorded bank rows with subnormal or
maximum-finite cell arguments, all 179 subnormal-input rows read back as +0 and match the +0
control (SQRT(-5e-324) is 0, SIGN(±5e-324) is 0, ODD(±5e-324) is 1, EVEN(±5e-324) is 0,
ISEVEN(±5e-324) is TRUE, ISODD(±5e-324) is FALSE, GESTEP(±5e-324) is 1, DELTA(±5e-324) is 1,
and a subnormal divisor or significance in QUOTIENT, CEILING or FLOOR flushes to 0). Formula
literals below 2.2250738585072014E-308 are refused at entry or parsed to 0. Products (*),
quotients (/) and probed powers (^) that fall in the subnormal range flush to +0, whereas + and
- retain subnormals and EXP(-745) holds 0x0000000000000001 in a formula cell. When fed a true
computed subnormal x from EXP(-745), EXP(-730) or EXP(-709) (and 0-x for negative), ABS(±x) is
x, SQRT(+x) is 2^-537, SQRT(-x) is #NUM!, EVEN(±x) is ±2, ODD(±x) is ±1, ISEVEN(±x) is TRUE,
ISODD(±x) is FALSE, CEILING(+x,1) is 1, FLOOR(-x,1) is -1, QUOTIENT(±x,1) is 0, DELTA(x,0) is
0, DELTA(x,x) is 1, GESTEP(+x,0) is 1 and GESTEP(-x,0) is 0, while SIGN(+x) and INT(-x)
transition inside the subnormal range (0 at 0x00000000001c7ea3 and ±1 at 0x0008bfe58468888d).

### FN-DELTA-001: DELTA and GESTEP read their second argument first

*Quirk; measured; recorded 2026-11-04.* Applies to DELTA, ERF, GESTEP.

When both arguments of DELTA or GESTEP are bad, the error comes from the second one:
DELTA(TRUE,#REF!) is #REF! and DELTA(#REF!,TRUE) is #VALUE!. With two errors, DELTA gives the
second. ERF reads left to right: ERF(TRUE,#REF!) is #VALUE! and ERF(#REF!,TRUE) is #REF!. A
logical is rejected in either position of these functions, whether typed or held in a cell:
DELTA(TRUE,0) and DELTA(2,TRUE) are #VALUE!, and DELTA(B1,0) with TRUE in B1 is #VALUE!, while
an empty B1 reads as 0 and gives 1.
