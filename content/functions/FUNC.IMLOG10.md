# IMLOG10

## What it does

`IMLOG10(inumber)` returns the principal base-ten logarithm of a nonzero complex value. The real component describes magnitude and the imaginary component describes angle.

## Try it

`=IMLOG10("i")` gives about `"0.682188176920921i"`. Its real component is zero because the modulus is one. The imaginary component is the principal phase `pi/2` divided by `ln(10)`. `=IMLOG10("100")` is approximately text two.

## Quirks

Complex arguments may be real numbers or text such as `"2-3i"`. Use lowercase `i` or `j`; operands in one call must agree on the suffix. The current parser rejects malformed complex text with `#NUM!` and logical values with `#VALUE!`. A complex result is text, so ordinary worksheet arithmetic does not automatically treat it as a pair of numeric components. Zero has no finite logarithm and the current kernel gives `#NUM!`. Principal angles create a branch cut on the negative real axis; a real-valued LOG call cannot replace this function.

## How to implement

Parse the two coefficients and suffix before doing arithmetic; use the common complex formatter afterward. Retain suffix consistency, suppress a zero component and omit the coefficient one before the imaginary unit. Formatting and parsing have their own fifteen-significant-digit rules, so testing only the algebra misses observable behaviour.

Compute a scaled modulus `h=hypot(a,b)` and principal angle `theta=atan2(b,a)`. Reject `h=0`. Form the natural-log pair `(ln(h),theta)`. Divide both components by the runtime natural logarithm of ten. For non-real input the current code uses runtime log and atan2 leaves. On the real axis its real component instead uses the measured public LN of the absolute input multiplied with stored x87 arithmetic by the binary64 constant `0x3fdbcb7b1526e50e`. The imaginary coefficient still uses the runtime phase and base logarithm. This mathematical composition does not identify all their rounding stages in Excel. In particular, preserve negative-real and signed-zero boundary tests rather than assuming that every logarithm wrapper shares IMARGUMENT’s ratio route.

### FN-IMLOG10-001: IMLOG10 multiplies Excel LN(|re|) by LOG10_E on the real axis and divides IMLN(z) by CRT ln(10) off-axis

*Detail for matching Excel's bits; measured; recorded 2026-11-22.*

In Excel 16.0 builds 20430 and 20527, IMLOG10(inumber) rejects 0 with #NUM!. When im = 0, its
real component is RN53(RN64(excel_log(|re|) * LOG10_E)) (while the imaginary part for re < 0 is
pi / crt_log(10)); off the real axis (im != 0), both components divide IMLN(z) by crt_log(10).
All 1,209 full-bank and 1,323 pinned IMLOG10 rows match.
